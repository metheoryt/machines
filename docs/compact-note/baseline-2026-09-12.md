# Compaction baseline — the "before" of the carry-over experiment

Frozen 2026-09-12, before `compact-note-save.sh` / `compact-note-restore.sh`
went live, from the local transcript archive (`~/.claude/projects/*/*.jsonl`,
2026-09-08 → 2026-09-11). Regenerate the table with
`scripts/compact-boundaries.py`; the `carried` column separates the two eras, so
one corpus holds both sides and no date cutoff is needed.

This file exists because the material expires. Transcripts are machine-local and
untracked, and a comparison run in October against a memory of September is not
a comparison.

## What compaction is

Not truncation. The model writes a summary of the conversation and the session
continues from that summary plus a preserved tail. Nothing is deleted — things
are lost by **omission**. So the question the experiment asks is not "how much
was dropped" but "was the dropped part needed".

## The numbers

| | |
|---|---|
| Boundaries | 51, across 6 projects |
| Trigger | **51 manual, 0 auto** |
| Tokens in → out | median 200,665 → 19,258 (~90% restated) |
| Range | 97,923 → 318,897 in; 10,378 → 26,444 out |

**All 51 were manual.** The auto-compact that fires without warning — the case
where "react before it happens" would matter most — has never happened on this
box. That reorders the whole problem: he compacts *on purpose*, which means
`/compact <instructions>` is already available at the moment of need, and the
hook pair is a convenience rather than a safety net. The day an `auto` row
appears in `scripts/compact-boundaries.py` output is the day that stops being
true.

## A metric that was tried and dropped

Counting files re-read after a boundary (re-discovery as a proxy for lost
context) does not work here: measured on a real boundary, 1 file touched before
and 5 after, 0 in common — because this fleet reads through `cat`/`sed` under
bypass-permissions, so `file_path` tool inputs barely exist. A Bash-command
parser would measure the parser. Dropped on purpose; recorded so it is not
re-invented.

A second guess also failed. The expectation was that the first user turn after a
boundary is unusually short — him re-pointing the model. It is not: median 59
characters against 51 for all his turns, 43% under 40 characters against 46%
overall. His turns are short everywhere.

## What the corpus does show

The distinguishing feature is the *kind* of turn, not its length. Of the 46
boundaries with a following user turn, roughly 19 are **bare continuations** —
instructions that carry no state of their own and require the model to
reconstruct what "phase 2", "the plan", or "the backfill" refers to from the
summary alone:

> `go inline` · `let's continue` · `давай продолжим` · `what's next?` ·
> `what's up` · `so, what's our next steps?` · `как наш процесс?` ·
> `что со сборкой?` · `let's implement` · `run the backfill` ·
> `let's go phase 2 inline` · `spec is good, let's write a plan` ·
> **`введи в курс дело кратко`** — literally *brief me*

The other ~27 open a new subject outright ("card-processing is an archive repo",
"давай подумаем, как ускорить походы в бд"). There the summary is sufficient by
construction, because the next turn does not depend on it.

**So the note can only matter on ~40% of boundaries**, and the experiment's
verdict should be read on those. A carried note that changes nothing on a
topic-switch boundary is not evidence against it.

## What to compare, later

For each new boundary, read the archived pair in
`~/.local/state/claude-compact/archive/` — `*-note.md` (what the shell froze)
next to `*-summary.md` (what the model wrote) — and the turns after it
(`scripts/compact-boundaries.py --after 8 -v`). Three questions:

1. On a **bare-continuation** boundary, did the first reply after the summary
   resume the actual work, or restate status and ask what to do?
2. Was anything in the note **absent from the summary** — a todo mid-flight,
   an uncommitted file, an instruction the summary paraphrased into something
   looser?
3. Did the note ever **mislead** — stale todos presented as current work? That
   is the failure mode that would argue for removing the pair, and it is why
   `compact-note-restore.sh` consumes the note and refuses one older than ten
   minutes.

## Check these on the FIRST compaction after the hooks go live

Three things are inferred from documentation rather than measured, and each one
fails silently:

- `~/.local/state/claude-compact/log.tsv` has a `save` row at all — hooks load at
  session start, so the pair is inert until a session started after they landed.
- That row's `keys=` column contains `transcript_path`. If it does not, the note
  degrades to git state only and every richer assertion above is moot.
- `scripts/compact-boundaries.py` flips `carried` to `True` for that boundary.
  If it does not, the group label is broken and the corpus cannot be split —
  worth knowing on day one rather than at verdict time.

A verdict needs boundaries of the bare-continuation kind, not calendar time.
At the historical rate (~19 of 51 over four days) that is days, not months —
but count them in `scripts/compact-boundaries.py` output rather than assuming.
